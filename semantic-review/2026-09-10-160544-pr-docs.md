# README/USAGE.md split — factual verification against Sources/

Splits the old single README into a short front-door README.md and a comprehensive USAGE.md manual, with the README linking out to USAGE.md for depth. USAGE.md's claims — action catalog, TrackPoint mechanics, App Switcher, keyboard shortcuts, tuning, permissions — were cross-checked against `Settings.swift`, `TrackPointController.swift`, `ActionExecutor.swift`, `AppSwitcherTab.swift`, `GestureEngine.swift`/`GestureProcessor.swift`, `HotkeyManager.swift`/`HotkeyTrigger.swift`, `TuningTab.swift`, `Info.plist`, and `Glide.entitlements`. The manual holds up well overall, including some genuinely tricky mechanics it gets right (TrackPoint's re-anchoring on overshoot, the double-tap window state machine, the exact list of actions hidden from the picker). **Watch for**: the App Switcher section implies window-level selection works in both presentation styles when it's actually Newer-only (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The action catalog in USAGE.md §3 matches `GestureAction.catalog` (Settings.swift) case for case, including the two app-switcher-internal actions (`appSwitcherNext`/`appSwitcherPrev`) that are correctly left out of the visible tables because `GesturesTab.swift` filters them from the picker. "Restore/Un-maximize Window"'s description ("previous size" and "or minimized") is accurate against `WindowTargeting.restore()`, which does branch on the minimized attribute.

The TrackPoint section (§5) is the strongest part of the manual — activation modes, the four tunable knobs, and the second-finger-to-scroll behavior all match `TrackPointController.swift` precisely, down to the "arming" hold-then-commit mechanic.

The App Switcher section (§4) correctly describes the two presentation styles and the reserved 3-finger horizontal swipe, but the window-selection sentence is written before the style distinction is introduced, so it reads as switcher-wide behavior. It isn't — vertical-swipe window picking only exists in the Newer overlay path.

The keyboard shortcuts section (§6), tuning section (§7), and permissions table (§10) all check out cleanly against their respective source files.

The table of contents anchors were checked by hand against the actual `##` heading text in the file; all 11 resolve correctly to their sections, no broken links found.

### App Switcher: window selection is Newer-only (confirmed)

USAGE.md §4 opens with: "How it works: swipe left or right with 3 fingers to browse apps. If an app has more than one window, swipe up or down to pick a specific window. Release to switch." This reads as a description of the switcher in general, before the "Two presentation styles" list distinguishes Newer from Legacy.

Reading `GestureProcessor.swift:108-140`, the vertical-swipe-to-select-window path only runs when `data.usesCustomOverlay` is true:

```
if data.usesCustomOverlay,
   data.windowsByApp.indices.contains(data.index),
   data.windowsByApp[data.index].count > 1 {
    let verticalIntent = abs(deltaY) > verticalThreshold && abs(deltaY) > abs(deltaX) * 1.15
    if verticalIntent { ... steps data.windowIndex ... }
}
```

`usesCustomOverlay` is only set `true` in `GestureEngine.beginAppSwitcher` when `Settings.shared.appSwitcher.style == .newer` and the overlay actually presents (`GestureEngine.swift:396-418`); the native fallback path (`usesCustomOverlay: false`, `GestureEngine.swift:441-454`) forwards left/right swipes straight into synthetic ⌘Tab/⌘⇧Tab key events and has no window-index concept at all. A user running Legacy mode who reads §4's opening paragraph and tries swiping up/down to reach a second window of an app will get no response — the doc's later "Legacy" bullet only says it lacks "per-window selection," which is correct, but by then the reader may have already formed the wrong expectation from the opening paragraph.

### Action catalog vs `GestureAction` enum — accurate

Every action name in USAGE.md §3's tables corresponds to a real `case` in `enum GestureAction` (Settings.swift:171-227), and the tables' grouping matches `GestureAction.catalog`'s category assignments exactly, including collapsing the four Snap corner variants into one table row. `appSwitcherNext`/`appSwitcherPrev` are correctly omitted from the visible tables — `GesturesTab.swift:336-339` filters them out of the Action picker via `Settings.isAppSwitcherAction`, so no end user ever sees "Next App (App Switcher)" as a pickable action; the doc matches what's actually reachable through the UI rather than the raw enum.

"Restore/Un-maximize Window — Returns a maximized (or minimized) window to its previous size" is accurate: `WindowTargeting.restore()` (WindowTargeting.swift:331-334) checks `axBool(w, attribute: kAXMinimizedAttribute...)` and un-minimizes if the target is minimized, falling through to the maximized-restore path otherwise.

### TrackPoint mechanics — accurate

The four activation modes in §5's table match `TrackPointActivationMode.displayName` exactly. The "second finger turns the stick into a scroller if scrolling is enabled" claim matches `mode(forContacts:)`'s check of `Settings.shared.trackPoint.scrollEnabled`. The four tunable knobs (top speed → `maxSpeed`, push distance → `pushRange`, dead zone → `deadZone`, acceleration exponent → `acceleration`) map onto real `TrackPointSettings` fields with matching semantics, and "move too far before the hold completes and Glide steps aside" matches the `arming` → `rejected` transition in `TrackPointController.swift`.

### Keyboard shortcuts, Tuning, Permissions — accurate

§6's "must include at least one modifier key" matches `HotkeyTrigger.isRegisterable` (`command || shift || control || option`) and the matching inline warning in `GesturesTab.swift:435-438`. §7's three presets match `TuningTab.swift`'s `Preset` definitions, and the permissions table matches the usage-description strings in `Info.plist` and the sandbox/automation entries in `Glide.entitlements`, including the correct "optional, falls back to icons" characterization of Screen Recording (confirmed against `AppSwitcherOverlay.swift:418-420`).
